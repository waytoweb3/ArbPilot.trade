# ArbPilot Twitter（X）运营计划

> 更新日期：2026-11-08
> 适用对象：ArbPilot 品牌号（英文为主），可另开一个创始人个人号做二次分发。
> 目标不是「涨粉」，而是让「懂资金费率/套利的交易者」在 90 天内知道 ArbPilot 并愿意来官网下载或注册。

## 0. 一页结论

- **定位**：不是「喊单号」，而是「用数据讲清算术的套利工具号」。可信度来自可复算的数字和对风险的坦白。
- **主线内容**：资金费率差数据（每天）+ 上币公告速报（事件驱动）+ 工程日志（每周）+ 教学长文（每周）。
- **节奏**：每天 1 条原创 + 5–10 条高质量回复；每周 1 个长 thread、1 篇工程日志、1 次周报。
- **产能**：每天 30–45 分钟，每周额外 2 小时批量写 thread。
- **转化路径**：X 帖子 → 官网数据页/下载 → Google 登录 → 免费版 → $49/$99。
- **红线**：不承诺收益、不说「无风险套利」、不喊单、不晒真实余额与密钥、不买粉不互关。

- 机会类内容注明样本范围：当前机会扫描默认只覆盖 BTC/ETH，资金费率采集覆盖全市场。
- 每条涉及交易的内容都带一句：`Data, not financial advice.`

### 3.2 格式规范

- **第一行必须是数字或冲突**：`23% annualized`、`$1.2B liquidated`、`Everyone says this is risk-free.`
- 一条只讲一件事；每段不超过 2 行；多用换行。
- 每条原创尽量配 1 张图：对比表、资金费率曲线、终端截图（打码余额与 Key）。
- 外链放在**第一条回复**里，正文不放链接（减少限流）。
- 标签最多 1–2 个，优先 `$BTC`、`$ETH`，不堆 hashtag。
- thread 每条独立可读；第 1 条给结论，最后 1 条给 CTA + 免责声明。
- 统一签名：`Data, not financial advice.`

## 4. 可直接套用的模板

### 4.1 资金费率雷达（单条）

```text
Funding spread radar — {date}

{ASSET}: {long_venue} pays {long_rate}% / 8h
vs {short_venue} at {short_rate}% / 8h

Spread ≈ {spread}% per 8h ≈ {annual}% annualized
Round-trip fees ≈ {fees} bps
Net per cycle ≈ {net} bps

Not free money — basis and leg risk still apply. Data, not advice.
```

计算口径写死，避免每次口径不一致：

```text
单次费率差 = 空头腿费率 − 多头腿费率
年化 = 单次费率差 × (24 / 结算间隔小时数) × 365
往返成本 ≈ 两腿手续费 + 预估滑点（默认每腿 4 bps，可按 VIP 档位调整）
净边际 = 单次费率差 − 往返成本
```

### 4.2 上币速报（公告后 15 分钟内）

```text
{exchange} just announced {ASSET} perpetual.

Checked funding across 8 venues:
{long_venue}: {rate}% / 8h
{short_venue}: {rate}% / 8h
Spread: {bps} bps at open

Watching: first-hour funding, book depth, whether the spread survives fees.
```

### 4.3 长 thread 结构（7 条）

1. 钩子：一个反直觉的数字或结论。
2. 大多数人的误解。
3. 机制：钱到底从哪来。
4. 成本账：手续费、滑点、资金费结算时点。
5. 风险：单腿失败、基差反向、交易所规则差异。
6. 如何自己验证：数据来源 + 截图 + 复算方法。
7. CTA：免费数据页/下载 + `Data, not financial advice.`

### 4.4 工程日志

```text
Shipped this week: {feature}

Why it matters: {user risk / workflow}
The tradeoff: {what we deliberately did NOT do}
What's still missing: {known limitation}

Screenshot of the actual UI below.
```

工程日志的重点是「取舍」而不是「功能列表」，这是最容易建立信任的内容。

### 4.5 脱锚/链上价格观察

```text
{ASSET} peg check

Uniswap V2 pool: {pool_price}
Chainlink oracle: {oracle_price}
Deviation: {bps} bps (alert threshold {threshold} bps)

A deviation is a fact, not a trade signal. Liquidity and redemption terms matter more.
```

### 4.6 长文结构（每月深度）

标题 → 一个具体数字开头 → 现象 → 机制拆解（配 1 张图）→ 成本与风险 → 如何验证 → 我们做了什么/没做什么 → 免责声明。

发布渠道：X long-form 或 thread 为主，Substack/Mirror 存档，官网后续可加 `/blog`（需要同步改 `seo.ts` 与 `PRERENDER_ROUTES`）。

## 5. 信息采集 → 文章的生产线

### 5.1 信息源分层

| 层级 | 来源 | 用途 | 频率 |
|---|---|---|---|
| T1 自有数据 | 本机执行器或官方只读实例的 `/funding/summary`、`/news`、`/chain/prices`、`/opportunities` | 独家数据卡片 | 每天 |
| T1 一手公告 | 5 家交易所公告页与官方 X | 上币速报 | 实时 |
| T2 行业媒体 | CoinDesk、The Block、Blockworks、DL News 的 RSS | 选题与背景 | 每天扫一次 |
| T2 数据站 | DefiLlama、CoinGecko、L2Beat、交易所 status 页 | 交叉验证 | 按需 |
| T3 社交 | X List（50 个交易/量化/交易所账号）、Telegram 公告频道 | 线索与情绪 | 每天扫一次 |

只读实例可直接拉数据（无需登录、只能读）：

```bash
curl -s "https://exec.arbpilot.trade/api/v1/funding/summary?secs=86400"
curl -s "https://exec.arbpilot.trade/api/v1/news?limit=50"
curl -s "https://exec.arbpilot.trade/api/v1/chain/prices"
curl -s "https://exec.arbpilot.trade/api/v1/opportunities"
```

注意：公开实例是只读镜像，别高频轮询；正式数据以自托管执行器为准。

### 5.2 每日采集清单（10 分钟）

1. 看一遍 5 家交易所新公告，记下时间、币种、合约类型。
2. 拉一次资金费率汇总，找当日费率差最大的 3 个标的。
3. 看链上价格偏离是否超阈值。
4. 扫一遍 RSS 标题，只记录「会改变交易者成本/风险判断」的 1–2 条。
5. 全部丢进一个「素材收件箱」（飞书表格/Notion），每条只写：时间 + 一句话 + 链接。

### 5.3 选题过滤 5 问

一条素材至少满足 3 条才写：

1. 它会改变交易者对费率/价差/风险的判断吗？
2. 我能加上别人没有的数据吗？
3. 10 分钟内能核实吗？
4. 24 小时后还有价值吗？
5. 它属于五个支柱之一吗？

### 5.4 核实规则

- 关键数字必须自己复算一遍，不直接抄截图。
- 至少两个独立来源；公告以交易所官方页面为准。
- 记录时间戳与数据快照，截图里保留时间。
- 区分「事实」「推测」「我们的观点」，不要混写。
- 涉及金额一律用「示例」，不引用自己或用户的真实账户。

### 5.5 一份素材 → 四种产物

| 产物 | 长度 | 用途 |
|---|---|---|
| 单条推文 | 3–6 行 + 1 图 | 抢时效 |
| Thread | 6–9 条 | 讲清机制 |
| 深度文章 | 800–1500 字 | 官网/Substack，长期搜索 |
| Telegram/日报 | 5–8 行 | 私域留存，导流付费 |

原则：**先发最快的单条，24 小时内补 thread，一周内沉淀成长文**。不要憋大招。

### 5.6 一个完整案例

1. 21:05 看到 Binance 公告上线 `XYZ` 永续。
2. 21:08 拉 8 家资金费率，算出首小时费率差与年化，截图。
3. 21:12 发单条速报（模板 4.2），第一条回复放官网链接。
4. 次日发 thread：新币上线首日资金费率的三种典型走势 + 成本账。
5. 周末把两次数据合并成「新币上线套利观察」长文。
6. 全程 40 分钟，产出 3 条内容。

## 8. 增长打法

1. **回复优先**：每天在 5–10 条高相关推文下留「带数据」的回复，比发 10 条原创更有效。目标账号：交易所官方、资金费率/衍生品数据号、量化交易者。
2. **抢公告**：上币公告是自然流量最大的时刻。提前把模板和脚本准备好，公告后 15 分钟内发出。
3. **Build in public**：每周固定一条工程日志，配真实截图。这是与竞品最大的差异。
4. **引用转发加数据**：只引用、不吵架；每条引用都要加一个自己的数字或图表。
5. **置顶 + 合集**：把优质 thread 做成「Start here」置顶，方便新访客一次看完。
6. **跨平台复用**：X → Telegram 日报 → 官网数据页 → Substack。不要把内容只留在 X。
7. **合作**：与 2–3 个中小账号做数据互换、联合 thread；不买粉、不互关、不做 giveaway。
8. **SEO 承接**：官网公开数据页（资金费率热力图/排行）是最便宜的落地页，帖子 CTA 指向它，而不是直接指向付费页。

## 10. 合规与红线

- 不承诺收益，不使用「无风险」「稳赚」「保证年化」等表述。
- 所有涉及交易的内容加 `Data, not financial advice.`。
