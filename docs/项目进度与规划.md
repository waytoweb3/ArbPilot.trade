## 3. 功能核查：非托管模式与托管模式

> **术语约定**
>
> - **非托管模式**：桌面端使用随包分发的**内置执行器**（代码里 `local`，界面文案「内置执行器」）。执行器只监听 `127.0.0.1`，密钥与凭证只在本机。
> - **托管模式**：桌面端连接**用户自建服务器上的执行器**（代码里 `self`，界面文案「自托管」），由用户自己运维主机与数据库。
> - 项目方的官方实例 `exec.arbpilot.trade`（`ARBPILOT_PUBLIC_MODE=true`）是**只读镜像**：只放行行情、资金费率、新闻与策略市场只读接口，账户密钥、下单、策略、风控、Telegram 一律 `403`。它**不属于**本文所说的托管模式，不能用来导入 Key、下单或创建策略。

### 3.1 结论速览

| # | 模式 | 核查项 | 结论 |
|---|---|---|---|
| 1 | 非托管 | 交易所 Key 能否导入、能否显示金额 | ✅ 支持 8 家，导入即校验并展示权益 |
| 2 | 非托管 | 资金费率套利 | ✅ 永续-永续资金费率差可用 |
| 3 | 非托管 | 新闻订阅 | ⚠️ 部分可用，仅 5 家交易所上币公告 |
| 4 | 非托管 | 新闻驱动策略 | ⚠️ 部分可用，仅「上币公告跟随」 |
| 5 | 非托管 | Telegram 手动下单 / 策略下单 | 手动 ✅（仅双腿）；策略 ❌ |
| 6 | 托管 | 能否配置执行器 | ✅ 支持，需自行处理网络暴露与 TLS |
| 7 | 托管 | 能否创建策略 | ✅ 支持，需 `arbitrage` + `strategy` 订阅权益 |

### 3.2 非托管模式

#### 3.2.1 交易所 Key 导入与金额显示：✅ 已实现

- **入口**：桌面端「设置 → 账户」（账户面板），执行器侧为 `POST /api/v1/accounts`。
- **支持范围**：8 家，与实盘下单范围一致。
  - CEX 5 家（`binance`、`okx`、`bybit`、`bitget`、`gate`）：API Key + Secret；`okx`、`bitget` 额外需要 Passphrase。
  - DEX 与 Aster 3 家（`hyperliquid`、`lighter`、`aster`）：钱包地址 + 签名私钥；Lighter 还可填 API Key 序号与账户索引。Aster 走 V3 API 钱包模型，填主账户地址 + API 钱包私钥，请求由本机 EIP-712 签名。不填签名私钥时只能查询余额，不能下单。
- **导入校验**：导入时先调该交易所私有接口拉一次余额，验证失败直接报错、不落盘，避免存下错 Key。
- **金额显示**：导入成功后展示总权益 `equity_usd`、各币种余额（面板显示前 3 个）、API Key 掩码、可交易状态；另有 24h / 7d / 30d 权益曲线，支持手动刷新与删除。
- **折算方式**：非 USDT 币种用 Binance 现货价格折算美元，价格缓存 60 秒。
- **安全边界**：凭证只写入本机 `accounts.json`（权限 `0600`），接口不回传 Key/Secret/私钥，只回传掩码预览。

#### 3.2.2 资金费用套利：✅ 可用（永续-永续）

- **已实现**：
  - 资金费率采集覆盖 Binance、OKX、Bybit、Bitget、Gate、Aster、Hyperliquid、Lighter 共 8 家的 USDT 本位永续，优先 WebSocket、失败回退 REST 轮转，历史保留 1 个月。
  - 机会模型「**永续-永续跨所资金费率差**」（`perp_perp_funding`）：同一币种在两家交易所的永续之间，做多费率低的一腿、做空费率高的一腿，不需要现货库存；各所结算间隔先折算成年化再比较。
  - 资金费率页支持排序与历史，点击机会跳转交易页并预填双腿（费率低的一腿做多、高的一腿做空）；确认后经 `POST /api/v1/orders` → 风控预检 → 实盘双腿下单。
- **已下线**：
  - 「同交易所现货做多 + 永续做空」的机会模型与内置「资金费率套利」策略已整体移除；历史 `funding_rate` 类型策略会被自动暂停并写入事件。
  - 现货盘口（`binance-spot`、`okx-spot`、`bybit-spot`）仅保留给交割基差与 K 线使用。
- **限制**：
  - 永续-永续机会当前只扫描 `ARBPILOT_MARKET_SYMBOLS`（默认 BTC/ETH），其它币种需要改配置。
  - 订单接口只有列表与创建双腿，**没有单腿下单、平仓、撤单接口**；平仓目前要靠再次创建反向订单或策略退出。
  - 下单回执即视为成交、重启不对账（见 P0）。

#### 3.2.3 新闻订阅：⚠️ 部分可用（只有上币公告）

- **已实现**：
  - 抓取 5 家交易所公告：Binance、Upbit、OKX、Bybit、Bitget（均为上币/新上线类）。
  - 桌面端新闻页可按来源开启/关闭订阅、记录已读、显示未读数；订阅偏好存在本机 `localStorage`。
  - 「设置 → 通知」可配置是否推送、来源白名单、资金费率年化阈值与冷却时间、渠道（桌面端、Telegram）。
  - 执行器侧 `GET /news`（官方只读实例也放行）。
- **限制**：
  - 没有商业新闻源、宏观/政策/项目动态，没有分类、情绪评分与影响评估。
  - 公告抓取依赖各交易所公开页面/接口，没有 SLA 与延迟承诺。
  - 订阅偏好只在本机，不随账号同步。

#### 3.2.4 新闻驱动策略：⚠️ 部分可用（只有上币公告跟随）

- **已实现**：
  - 内置模板「上币公告跟随」（`listing-follow`）：执行器只向策略注入最近 `event_window_secs`（默认 3600 秒）内、**标题命中该策略交易对**的上币公告；公告发布后 15 分钟内市价做多，持有 6 小时后平仓。
  - 事件按 `event_sources`、`event_keywords`、`event_window_secs` 过滤，可在策略的 scope 里改；策略交易对/交易所也可配置。
  - 策略发出的开平仓仍经统一网关 `gateway::submit_pair`（或单腿入口）与 `RiskEngine::preflight`，来源标记为 `OrderOrigin::Strategy`。
- **限制**：
  - 只有「公告 → 做多」这一种事件语义，没有基于新闻情绪、宏观数据或任意新闻正文的通用驱动策略。
  - 事件窗口外不触发；策略仍受持仓状态、冷却时间与风控限额约束。
  - 回测注入的事件列表为空，事件类策略在回测中不会触发，只能用实盘/演练验证。

#### 3.2.5 Telegram：手动下单 ✅（仅双腿）；策略下单 ❌

- **手动下单（支持）**：
  - 命令：`/open <交易对> <多头交易所> <空头交易所> <每条腿USD> [杠杆]` 生成待确认单并以「确认开仓 / 取消」内联按钮回复；点击确认后调用 `gateway::submit_pair`，来源 `OrderOrigin::Telegram`，同样过风控；点击取消只撤销待确认单（按钮回调携带编号，无需手输）。
  - 其它命令：`/status`、`/positions`、`/orders`、`/news`、`/unbind`。
  - 绑定：配对码 `/bind` + 白名单，绑定权限需含 `trade`；待确认单有过期时间与数量上限。
- **限制**：
  - **只能开双腿对冲仓**，没有单腿下单、平仓、改单、撤交易所挂单的指令。
  - **策略不会被 Telegram 触发**：策略由执行器按行情/事件自行运行，Telegram 只能查询状态；是否允许策略自动开仓仍是待决策项。
  - 需要 `ARBPILOT_TELEGRAM_BOT_TOKEN`。内置执行器启动时未注入该变量（只设置了监听地址、令牌、SQLite、账户/风控/授权/绑定文件等），本地模式要生效需从终端带该环境变量启动桌面端让 sidecar 继承，或改用自托管执行器。

### 3.3 托管模式（连接用户自建服务器执行器）

#### 3.3.1 配置执行器：✅ 已实现

- **入口**：桌面端「设置 → 执行器」，切换「内置执行器 / 自托管」。
- **配置项**：执行器地址（`https://exec.example.com` 或 `http://IP:8787`）+ API 令牌（服务端 `ARBPILOT_API_TOKEN`）。两种模式各自保存地址与令牌，切换不会互相覆盖；保存时规范化 URL，改地址或切模式后自动重载。
- **服务端要求**：
  - 执行器默认只绑 `127.0.0.1`；要直连 IP 需 `ARBPILOT_EXECUTOR_HOST=0.0.0.0`（Compose 端口映射）并放行 8787。
  - 自托管可设 `ARBPILOT_LICENSE_REQUIRED=false` 关闭授权校验。
- **限制**：执行器管理端口无内建 TLS、CORS 仍为 `Any`、默认令牌是开发值，远程使用应走 SSH 隧道/VPN（P0「远程接入安全」）；桌面端目前只能连一个执行器（P1「多执行器管理」）。

#### 3.3.2 创建策略：✅ 已实现（有订阅门槛）

- **入口**：「策略 → 新建」，两种方式：
  - 空白创建：填名称（可选填自然语言需求让 AI 生成 WAT 源码，或自己写代码）→ `POST /api/v1/strategies`，无定义时生成默认 `Custom` 定义。
  - 模板实例化：海龟突破、均线趋势、网格、上币公告跟随 → `POST /api/v1/templates/{key}/instantiate`。
- **创建后可做的事**：保存/编译/部署代码到 WASM 沙箱、设置 scope（交易对、交易所、`event_*`）、校验、回测、启停、版本回滚、删除；`run_scope` 可选自托管或平台侧运行。
- **订阅门槛**：需要 `arbitrage` 基础订阅 + `strategy` 附加包；只有基础版时每个计费周期含 3 天试用，试用结束只可查看不可创建（桌面端按钮会提示所需套餐）。
- **限制**：官方只读实例不允许创建策略（`403`）；策略创建不影响 P0/P1 中列出的回测精度与成交确认限制。

## 4. 未完成项

### P0：影响实盘正确性与安全，优先处理

- [ ] **成交确认与对账**：当前每条腿在收到交易所「下单回执」后即标记为已成交，未轮询订单状态，也未处理部分成交、撤单与改单；执行器重启后不会与交易所核对挂单和真实持仓。  
  影响：真实成交价/数量可能与本地记录不一致，补偿动作依赖人工判断。
- [ ] **自动风控停摆**：只在「一腿成交、另一腿失败」时自动暂停。行情过期、连续下单失败、账户余额异常、资金费率异常等场景只会拒单或记录事件，不会自动暂停并升级告警。
- [ ] **远程接入安全**：执行器管理端口没有内建 TLS、中继或受控出网连接，远程使用需用户自行架设 SSH 隧道/VPN；CORS 仍为 `Any`，默认令牌为开发值。
- [ ] **升级备份与回滚**：部署与升级脚本未自动备份 PostgreSQL，也未实现升级失败自动回滚；文档中的备份步骤依赖人工执行。
- [ ] **补偿自动化**：失衡后仅暂停等待人工确认，未实现自动撤单、反向对冲或按策略定义回滚。

### P1：核心功能缺口

- [ ] **CEX-CEX 价差扫描**：`OpportunityKind::CexCexSpread` 只有枚举，扫描器仍只计算资金费率机会。
- [ ] **CEX-DEX 价差扫描**：`CexDexSpread` 未实现；链上价格监听已能读取 Uniswap V2 池子储备与 Chainlink 预言机（`GET /api/v1/chain/prices`），但还没有可成交深度、兑换路径与下单能力。
- [ ] **新闻能力**：目前只有交易所上币公告（Binance、OKX、Bybit、Bitget、Upbit），无商业新闻源、分类/情绪、影响评估；新闻自动交易仅有「上币公告跟随」模板。
- [ ] **回测精度**：逐根 K 线重放、收盘价成交、无盘中价格路径、配对开仓按零基差、无盘口深度与冲击成本、单交易所单品种分别回放、最多 720 根 K 线、样本外仅按 7:3 切分，无滚动验证与参数寻优过拟合提示。

## 5. 后续功能规划

规划按依赖关系排序，不设固定日期；每一项以「可验证的完成标准」收口。

### 阶段 A：实盘可信（P0）

目标：让策略和手动交易在真实市场里可核对、可恢复、可止损。

1. 订单生命周期：下单后轮询/订阅成交，记录部分成交、成交均价与手续费，支持撤单与改单。
2. 启动对账：执行器启动时拉取未完成订单与真实持仓，对账后再恢复策略；不一致时保持暂停并告警。
3. 自动风控：行情过期、连续失败、余额异常、资金费率突变触发自动暂停，并通过 Telegram/桌面端升级告警。
4. 补偿自动化：双腿失衡时按策略定义自动撤单/反向对冲，保留人工接管入口。
5. 升级安全：升级前自动 `pg_dump` 备份，健康检查失败自动回滚。
6. 远程接入：提供受控出网连接或内置 TLS/中继方案，替换 `Any` CORS 与默认令牌。
7. 验收：模拟交易所故障、部分成交、断线重启、升级失败四类演练全部通过，且订单与交易所记录一致。

### 阶段 B：机会与执行扩展（P1）

1. CEX-CEX 价差：同币种跨所买一/卖一对比，计入手续费、滑点、深度与可成交额度，输出净价差排序。
2. CEX-DEX 价差：接入 Hyperliquid/Lighter 报价与深度，后续再评估其他链与 DEX。
3. 机会页执行：从机会一键生成双腿订单，预填金额、杠杆、滑点与风控限额。
4. 历史事件：记录机会出现/消失的时间序列，用于复盘与阈值调优。
5. 验收：至少两个交易对在两个交易所能稳定产出机会，回测与实盘价格偏差可解释。

### 阶段 C：策略与回测（P1）

1. 回测升级：多品种同步回放、盘口深度与冲击成本、可配置成交模型、资金费率结算重放。
2. 验证升级：滚动样本外、参数敏感性、过拟合提示，回测报告固定展示假设与样本区间。
3. AI 辅助升级：先澄清交易所/品种/成本/退出条件，再产出结构化草案与解释；支持用户自带模型 Key 与关闭 AI。
4. 策略模板扩展：增加资金费率对冲、跨所价差等模板，模板可参数化实例化。
5. 验收：同一策略定义在回测与实盘使用同一套意图与风控路径，报告可复现。

### 阶段 D：策略市场商业化（P1/P2）

1. 分账与结算：作者收入、平台服务费、结算周期与对账单；对接支付服务商打款能力。
2. 订阅体验：试用期、评分与评论、版本更新通知、撤回后的处置说明。
3. 风控与治理：发布审核、风险事件公告、违规下架，且不影响使用者查看与处置已有仓位。
4. 验收：一笔真实订阅从下单、开通、续费、取消到作者结算全链路可追踪。

### 阶段 E：工程与发布（P2）

1. GitHub Actions：Rust 检查与测试、前端类型检查与构建、镜像发布、桌面多平台打包。

4. 测试补齐：PostgreSQL 集成测试、交易所适配录制回放、前端关键流程 E2E。

### 阶段 G（建议，待决策）：事件雷达与脱锚监控

6. 验收：用 1011/1030 两段历史切片回放，事件发生后 5 分钟内能回答「哪个资产偏离、偏离多少、锚定依据是否成立、账户最坏亏多少」，且全程不产生自动订单。

## 6. 候选功能池（发散，未排期）

> 本节是发散记录，不是承诺排期。列入「阶段 A–F」的才算已计划，阶段 G 是待决策建议；这里只记录「值得做但还没定序」的想法，供后续取舍。
>
> 排序原则：优先让真实用户敢跑真实仓位，其次才是功能数量。

### 6.1 把「能跑」变成「敢跑」

投入小、直接决定留存，建议优先于任何新玩法。

| 候选 | 现状缺口 | 完成标准 |
|---|---|---|
| 一键脱困（撤全部挂单 + 平全部仓位） | 订单接口只有列表与双腿开仓，无平仓、撤单、改单 | 桌面端与 Telegram 各一个入口，双腿同平、二次确认、全程审计 |
| 每日对账摘要 | 下单回执即视为成交，重启不对账 | 每日定时比对本地记录与交易所快照，差异推送到 Telegram，不一致自动暂停策略 |
| 账户风险体检 | 无保证金视角 | 给定当前持仓，模拟价格 -10%/-20% 的维持保证金率与强平距离 |
| 每日最大亏损停机 | 风控只覆盖单笔与总仓位 | 风控页可配当日亏损上限，触发后强制冷却并告警 |
| 影子运行（shadow run） | 策略只能实盘或回测，缺中间态 | 策略新增「影子」运行态：只记录意图不下单，N 天后输出「若执行会怎样」的报告 |
| 费率档位配置 | `LEG_FEE_BPS` 在 `market.rs` 写死为 4bps/腿 | 用户可填 VIP 等级或自定义 maker/taker 费率，机会净收益按实际费率重算 |

### 6.2 机会扩容

按性价比排序，而不是按听起来高级排序。

1. ~~**补齐现货盘口到 Bitget / Gate**~~：现货-永续机会已下线，此候选作废。
2. ~~**永续-永续资金费率差**~~：✅ 已实现，8 家永续盘口均已接入；下一步是把扫描币种从默认 BTC/ETH 扩到各家全部 USDT 永续。
3. **期现基差回归**：同一数据源多一种退出逻辑，除吃资金费外还吃基差收敛。
4. **机会存活时间统计**：记录机会从出现到消失的时长中位数，回答「手工来得及吗、值得自动化吗」。数据已采集，只差聚合。
5. **阈值反查**：用过去 30 天历史机会回答「设 15bps 门槛会开多少次、平均持有多久」，比完整回测便宜，说服力更强。
6. **CEX-CEX 价差**：与资金费率是完全不同的工程（双所盘口同步、延迟敏感、时钟偏移敏感），排在补齐现货盘口之后，且先做「只提示不自动执行」。

### 6.3 执行质量

用户不为「能下单」付费，为「下得好」付费。

- **被动腿优先（maker-first）**：先挂 maker 腿等成交，再打 taker 腿，可省掉近一半手续费。专业与业余套利的分水岭。
- **按盘口深度拆单**：单笔超过盘口一定比例时自动分批，避免自己吃掉价差。
- **组合级风控**：多策略并行后会出现「每个策略都没超限、加起来爆仓」，需要跨策略/跨所的统一敞口与保证金视图。
- **时钟偏移检测**：交易所时间与本机偏差超阈值告警。
- **资金划转建议（只建议不自动）**：跨所保证金不足时给操作建议，绝不自动提币。
- **时段保护**：非交易时段、重大数据发布前后自动收紧限额。

### 6.4 数据与研究

- **参数网格扫描 + 热力图**：一次跑 N 组参数输出热力图，同时是「过拟合提示」最直观的载体。
- **资金费率季节性/预测**：历史同期均值与下次结算预估，轻量、高频使用。
- **回测报告可分享链接**：脱敏只读，可嵌入策略市场卡片，把回测变成可信凭证。
- **数据导出 CSV/Parquet**：付费用户需求明确，实现成本低。
- **K 线按需缓存**：先做「最近 N 天按需缓存」，确认用量后再谈数据湖。

### 6.5 商业化与增长

- **免费版钩子**：日报 + 每日 3 条机会推送（Telegram），比「只读网页」更能驱动付费转化。
- **交易所返佣对接**：套利用户交易量大，返佣既降成本又形成收入，需做好披露。
- **官网公开数据页**：把 `apps/site` 的 `LiveSpread` 扩成全市场资金费率热力图/排行，无需登录即可访问，是成本最低的获客与 SEO 渠道。
- **定价分档**：按「交易所账户数 × 策略数」分档，比只切 $19/$29 两刀更自然。

### 6.6 被低估的两块

1. **小团队/机构向**：多角色权限（只读交易员 / 风控管理员 / 出资人）、按策略维度的 PnL 归因、操作审计。竞品基本没做，付费能力最强。最小版可先做「只读子账号 + PnL 归因」。
2. **Webhook / 开放 API**：让 TradingView、自建脚本触发执行器。网关已有，接入成本低、粘性高，也顺带解决「用户想接自己的策略」。

### 6.7 明确暂不做

- 三角套利、跨链桥套利、借贷/质押利率套利：工程与合规风险远超当前阶段收益。事件期的脱锚观测、执行路径计算与人工清单不在此列，归入 6.9；但自动跨链、自动借贷循环仍不做。
- 社区、策略评论区、社交 feed：早期用邀请制 + Telegram 群替代。
- 大模型在实盘路径里逐笔决策：与项目原则冲突。
- 自研撮合、自研行情中继。

### 6.8 若只做三件

1. **扩展永续扫描范围**：把扫描币种从默认 BTC/ETH 扩到 8 家交易所的全部 USDT 永续。
2. **一键脱困 + 每日对账**：把「敢不敢用」变成「敢用」。
3. **影子运行**：同时解决新用户上线门槛与策略市场可信度。

补充一条判断：P0 的「远程接入安全」不必自研中继，优先评估集成 Tailscale / Cloudflare Tunnel 的出站连接，成本远低于自建 TLS 网关。

### 6.9 专题：事件驱动与极端行情（1011 / 1030 复盘映射）

> 素材是 2026-11-07 的复盘笔记（连环清算 + 交易所被盗）。这里把这套人工 playbook 拆成「看得见 → 算得清 → 做得对」三层，只保留现有架构能承接的部分。本节属候选记录，不承诺排期；对应阶段建议见第 5 节「阶段 G」。

#### 6.9.1 结论

1. 现有能力覆盖的是常态下的资金费率与基差。事件期最关键的**异常波动、地址行为、锚定偏离、清算流**四类数据基本空白。
2. 「抄底 / 做黑客对手盘 / 循环套利」的执行链条涉及提币、跨链、链上兑换与项目赎回，超出当前「CEX 双腿下单」的边界，短期只做观测、计算与人工执行清单。
3. 成本最低、又能复用现有行情、告警与风控的切入点是三件事：**事件雷达（跌幅与波动）+ 危机模式（限额与压测）+ 锚定监控（稳定币/LST）**。

#### 6.9.2 复盘要点与现状对照

| 复盘要点 | 现有能力（证据） | 缺口 | 判定 |
|---|---|---|---|
| 链上 + 交易所、交易所 + 交易所的异常波动 | 8 家永续维护买一/卖一（`Quote` 只有 bid/ask/时间），现货盘口仅用于交割基差与 K 线；`OpportunityKind` 已有 `CexCexSpread`、`CexDexSpread` 枚举 | 无 24h 涨跌幅、成交额与跨所波动扫描；两个枚举没有对应扫描器 | ⚠️ 部分 |
| 黑客地址与资金流向 | 无 | 无地址 watchlist、地址标签库、CEX 充值地址识别，也没有链上/CEX 价差聚合视图 | ❌ 缺失 |
| 巨鲸地址与仓位 | 无；`state.positions` 只记录本机订单产生的内存仓位 | 无外部地址持仓数据，也无「长期大户突然平对冲仓」这类变化检测 | ❌ 缺失 |
| 资金规划与头寸控制 | `RiskEngine::preflight` 管单笔 5,000 USD、总敞口 25,000 USD、杠杆 10、滑点 25bps、行情 5 秒、交易所白名单；交易对默认不限制 | 无当日亏损上限、保证金/强平视角、事件模式限额、场景压测，也没有下单前「最坏亏多少」的强制确认 | ⚠️ 部分 |
| 跌幅榜与流动性博弈 | 有永续盘口与 K 线；现货腿已下线，事件期实际只能做合约 | 无跌幅榜、成交额与池子 TVL、流动性评分；`ARBPILOT_MARKET_SYMBOLS` 默认只有 BTC/ETH | ⚠️ 部分 |
| 稳定币脱锚 | `onchain.rs` 可配置「Uniswap V2 池子 vs Chainlink」并输出偏离 bps，超阈值告警 | 无 1:1 锚定视图、无赎回机制与额度、无多预言机（RedStone/Chronicle）、无 CEX 现货价对比、无历史脱锚分位 | ⚠️ 部分 |
| LST / 封装资产（BETH、BNSOL、WBETH） | 同一套 chain feed 可以手工配池子与预言机 | 只支持 V2 池子；无理论汇率（质押率）；无对应现货盘口，双腿订单会因缺行情被直接拒绝 | ⚠️ 只能看，不能做 |
| WBETH/ETH 汇率 + 合约对冲 | 双腿订单与 `reduce_only` 平仓已具备 | 没有 WBETH 现货腿行情，`submit_legs` 会拒绝；也没有 ETH 永续对冲的自动配对 | ❌ 当前不可执行 |
| Pendle YT / 波动率 | 无 | 无 Pendle、期权（含 BTC 隐含波动率与偏斜）与金库类数据 | ❌ 缺失 |
| 赎回机制、跨链桥、循环套利 | 无提币、跨链与链上兑换能力（DEX 仅 Hyperliquid/Lighter 可下单） | 整条链路没有任何一步能自动执行 | ❌ 缺失 |
| 交易所与 DEX 清算机制 | 无清算数据 | 需要第三方数据源或自建节点，成本与 SLA 未评估 | ❌ 缺失 |
| 账号、落地 IP、资金通道（USDT → Plasma → 交易所） | 属运维事项 | 不是产品功能，只在文档给检查清单 | — |

#### 6.9.4 边界

- **只观测不执行**：自动跨链、自动提币、项目赎回、Pendle/期权交易、地址跟单继续不做；产品最多给出路径、成本与清单。
- **不给结论**：页面只呈现「偏离事实 + 锚定依据 + 风险清单」，不回答「该不该抄底」。否则产品会变成喊单工具，同时引入投资建议合规风险。
- **数据可关**：事件类数据源必须允许整体关闭，并明示延迟与覆盖范围；离线或降级时不能静默使用过期数据下单。

#### 6.9.5 阶段建议

建议单列第 5 节的「阶段 G（建议，待决策）」，排在阶段 A 之后、阶段 C 之前，与阶段 B 并行。若资源只够做一件事，先做事件雷达：它复用现有行情与告警，不依赖外部数据采购，也是其余事件能力的数据底座。
