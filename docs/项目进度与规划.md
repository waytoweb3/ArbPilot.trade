## 1. 本次提交内容

本次提交把「策略」链路从骨架补齐为可运行闭环，并接入通知与配置：

- 策略沙箱：Wasmtime 执行、ABI v2（行情、K 线、指标、上币事件、持仓、开平仓、挂单/撤单）、CPU/内存/输出限制。

## 3. 未完成项

### P0：影响实盘正确性与安全，优先处理

- [ ] **成交确认与对账**：当前每条腿在收到交易所「下单回执」后即标记为已成交，未轮询订单状态，也未处理部分成交、撤单与改单；执行器重启后不会与交易所核对挂单和真实持仓。  
  影响：真实成交价/数量可能与本地记录不一致，补偿动作依赖人工判断。
- [ ] **自动风控停摆**：只在「一腿成交、另一腿失败」时自动暂停。行情过期、连续下单失败、账户余额异常、资金费率异常等场景只会拒单或记录事件，不会自动暂停并升级告警。
- [ ] **远程接入安全**：执行器管理端口没有内建 TLS、中继或受控出网连接，远程使用需用户自行架设 SSH 隧道/VPN；CORS 仍为 `Any`，默认令牌为开发值。
- [ ] **升级备份与回滚**：部署与升级脚本未自动备份 PostgreSQL，也未实现升级失败自动回滚；文档中的备份步骤依赖人工执行。
- [ ] **补偿自动化**：失衡后仅暂停等待人工确认，未实现自动撤单、反向对冲或按策略定义回滚。

### P1：核心功能缺口

- [ ] **CEX-CEX 价差扫描**：`OpportunityKind::CexCexSpread` 只有枚举，扫描器仍只计算资金费率机会。
- [ ] **CEX-DEX 价差扫描**：`CexDexSpread` 未实现；Hyperliquid/Lighter 仅支持余额查询与下单签名，没有链上/DEX 报价与深度。
- [ ] **新闻能力**：目前只有交易所上币公告（Binance、OKX、Bybit、Bitget、Upbit），无商业新闻源、分类/情绪、影响评估；新闻自动交易仅有「上币公告跟随」模板。
- [ ] **回测精度**：逐根 K 线重放、收盘价成交、无盘中价格路径、配对开仓按零基差、无盘口深度与冲击成本、单交易所单品种分别回放、最多 720 根 K 线、样本外仅按 7:3 切分，无滚动验证与参数寻优过拟合提示。
- [ ] **AI 策略辅助**：目前直接生成 WAT 源码；缺少项目说明中的澄清追问、结构化草案（YAML/JSON Schema）、自然语言解释、回测解读与隐私范围提示。
- [ ] **策略市场商业化**：作者分账/提现、平台服务费、退款与争议流程未落地；缺少评分、评论、试用期、版本撤回后的订阅者通知。
- [ ] **多执行器管理**：桌面端只连接一个执行器地址，无多设备/多服务器切换与统一视图。
- [ ] **通知渠道**：仅 Telegram 与桌面端事件，无邮件、Webhook、移动推送。
- [ ] **数据存储**：K 线不落库；资金费率只保留 1 个月；未评估 TimescaleDB 或冷数据归档。
- [x] **本地模式数据库**：桌面端随包启动执行器并使用本机 SQLite（`ARBPILOT_LOCAL_DB`），用户零配置，无需自备 PostgreSQL。

### P2：工程质量与运维

- [ ] **CI/CD**：仓库没有 `.github/workflows`，构建、测试、镜像与发布靠本地脚本。
- [ ] **代码签名与公证**：桌面端已配置签名更新公钥，但 Windows/macOS 代码签名、公证与发布渠道未形成流水线。
- [ ] **可观测性**：只有 `/api/v1/health` 与 tracing 日志，无 Prometheus 指标、日志聚合、外部告警。
- [ ] **测试覆盖**：Rust 有 92 个单元测试；缺少 PostgreSQL、交易所适配、网关补偿路径的集成测试；前端无单元测试与 E2E。
- [ ] **前端性能**：主包约 777 kB（gzip 235 kB），需要按路由拆包。
- [ ] **国际化**：仅中英双语。

### P3：商业化与合规

- [ ] 支付服务默认 `WAFFO_ENVIRONMENT=test`，切换到生产需重新配置商品、私钥与回调域名。
- [ ] 套餐权益边界、数据额度、设备数、取消订阅后的行为尚未写死到产品与代码。
- [ ] 退款、争议、税务、作者结算周期与平台费率未定稿。
- [ ] 法务文本仍有占位内容（如 DPO 暂未设立），需按目标销售地区复核。
- [ ] `ArbPilot.trade` 域名、商标与同名产品核查未完成。

## 4. 后续功能规划

规划按依赖关系排序，不设固定日期；每一项以「可验证的完成标准」收口。

### 阶段 A：实盘可信（P0）

目标：让策略和手动交易在真实市场里可核对、可恢复、可止损。

1. 订单生命周期：下单后轮询/订阅成交，记录部分成交、成交均价与手续费，支持撤单与改单。
2. 启动对账：执行器启动时拉取未完成订单与真实持仓，对账后再恢复策略；不一致时保持暂停并告警。
3. 自动风控：行情过期、连续失败、余额异常、资金费率突变触发自动暂停，并通过 Telegram/桌面端升级告警。
4. 补偿自动化：双腿失衡时按策略定义自动撤单/反向对冲，保留人工接管入口。
5. 升级安全：升级前自动 `pg_dump` 备份，健康检查失败自动回滚。
6. 远程接入：提供受控出网连接或内置 TLS/中继方案，替换 `Any` CORS 与默认令牌。
7. 验收：模拟交易所故障、部分成交、断线重启、升级失败四类演练全部通过，且订单与交易所记录一致。

### 阶段 B：机会与执行扩展（P1）

1. CEX-CEX 价差：同币种跨所买一/卖一对比，计入手续费、滑点、深度与可成交额度，输出净价差排序。
2. CEX-DEX 价差：接入 Hyperliquid/Lighter 报价与深度，后续再评估其他链与 DEX。
3. 机会页执行：从机会一键生成双腿订单，预填金额、杠杆、滑点与风控限额。
4. 历史事件：记录机会出现/消失的时间序列，用于复盘与阈值调优。
5. 验收：至少两个交易对在两个交易所能稳定产出机会，回测与实盘价格偏差可解释。

### 阶段 C：策略与回测（P1）

1. 回测升级：多品种同步回放、盘口深度与冲击成本、可配置成交模型、资金费率结算重放。
2. 验证升级：滚动样本外、参数敏感性、过拟合提示，回测报告固定展示假设与样本区间。
3. AI 辅助升级：先澄清交易所/品种/成本/退出条件，再产出结构化草案与解释；支持用户自带模型 Key 与关闭 AI。
4. 策略模板扩展：增加资金费率对冲、跨所价差等模板，模板可参数化实例化。
5. 验收：同一策略定义在回测与实盘使用同一套意图与风控路径，报告可复现。

### 阶段 D：策略市场商业化（P1/P2）

1. 分账与结算：作者收入、平台服务费、结算周期与对账单；对接支付服务商打款能力。
2. 订阅体验：试用期、评分与评论、版本更新通知、撤回后的处置说明。
3. 风控与治理：发布审核、风险事件公告、违规下架，且不影响使用者查看与处置已有仓位。
4. 验收：一笔真实订阅从下单、开通、续费、取消到作者结算全链路可追踪。

### 阶段 E：工程与发布（P2）

1. GitHub Actions：Rust 检查与测试、前端类型检查与构建、镜像发布、桌面多平台打包。
2. 签名与公证：Windows/macOS 签名、公证、增量更新与回滚验证。
3. 可观测性：Prometheus 指标（延迟、拒单原因、腿失衡、授权状态）、日志聚合与告警。
4. 测试补齐：PostgreSQL 集成测试、交易所适配录制回放、前端关键流程 E2E。
5. 前端拆包与性能预算。

### 阶段 F：增值能力（P2/P3）

1. 商业新闻源接入：授权、分类、时间戳、影响观察与告警；新闻自动交易保持独立开关与低风险默认值。
2. 多执行器：统一管理多台自托管执行器，按策略分配运行位置。
3. 通知渠道扩展：邮件、Webhook、移动推送。
4. 存储扩展：K 线落库、TimescaleDB/对象存储归档、数据额度计量。
