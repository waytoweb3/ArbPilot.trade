# ArbPilot 自托管部署指南

本文写给需要把执行器放到**自己的服务器**上的用户。桌面端只负责配置与监控，交易所 API Key、签名私钥与下单签名全部留在执行器所在机器。

部署和升级都在客户端「文档」页完成：填一次服务器登录信息（只存本机钥匙串）→ 检查版本 → 点按钮。不需要 `git clone`，也不需要登录服务器敲命令。

## 先选模式

| | 官方托管（默认） | 自托管 |
|---|---|---|
| 买服务器 | 不需要 | 需要，本文第 1～3 步 |
| 部署方式 | 不需要 | 客户端「文档」页一键部署，或登录服务器执行 `curl -fsSL https://download.arbpilot.trade/executor/install.sh \| sudo bash` |
| 配置执行器地址、令牌 | **不需要**，客户端已内置默认值 | 部署完成后自动回填，本文第 4 步只需开隧道 |
| 密钥存放 | 官方执行器 | 你自己的服务器 |
| 适合 | 想直接开始用、以监控与小额交易为主 | 资金量大、要求凭证不出自己的机器 |

非自托管用户装好客户端后直接登录使用即可，**不要**在设置页改地址或令牌；如果之前填过自托管地址，把地址与令牌清空后点「保存并连接」，就会回到内置默认值。

> 登录与订阅走官方账号服务（Google 账号绑定）；执行器只负责行情、账户余额、风控与下单，自托管不会影响登录。

## 架构

```
发布源（download.arbpilot.trade/executor/manifest.json）
   │  版本号 + 包地址 + sha256
   ▼
桌面端（你的电脑）
   │  SSH 部署 / 升级          Bearer 令牌 + SSH 隧道
   ▼                            ▼
执行器（你的服务器，127.0.0.1:8787）
   ├── PostgreSQL（余额、权益、策略、订单记录）
   └── data/（交易所 API Key、签名私钥、风控限额、Telegram 绑定）
```

执行器端口默认**只绑定回环地址**，桌面端通过 SSH 隧道（推荐）或带证书的反向代理连接；托管模式也支持直接填服务器 IP，见第 4 步。

## 登录、订阅与授权

ArbPilot 的托管与非托管用户统一使用 Google 第三方账号登录，账号服务不保存密码，也不接触交易凭证：

- **桌面端**：右上角头像 →「使用浏览器登录」，在浏览器里完成 Google 授权后回到客户端；会话只保存在本机，退出登录即清除。
- **官网**：只做展示，提供价格与安装包下载；登录、订阅、设备管理与退订都在桌面端完成。
- **订阅绑定账号**：收银台必须携带登录会话，未登录会被支付服务拒绝；支付成功后订阅归属该账号，换设备或重装后重新登录即可恢复。
- **设备**：首次登录会登记本机设备，套餐限制同时在线设备数，可在桌面端「设置 → 订阅与账单」管理设备与订阅。

执行器侧的授权是**可选的离线校验**，默认关闭：

1. 登录后桌面端向账号服务换取短期 Ed25519 令牌（`POST /api/me/license-token`），再写入执行器（`POST /api/v1/license`）。
2. 执行器只用内置公钥验签，不联网；令牌保存在容器的 `data/license.json`（权限 600），重启自动恢复。
3. 开启校验后，套利与策略相关接口按套餐返回 `402 license_required`；令牌过期后仍有 `ARBPILOT_LICENSE_GRACE_HOURS`（默认 72 小时）的离线宽限。
4. 自托管默认 `ARBPILOT_LICENSE_REQUIRED=false`，执行器本身不强制校验；产品规则上自托管部署需要 $49/月 基础订阅，基础版每个计费周期前 7 天可免费创建策略，之后创建策略再加 $50/月。官方托管实例按用户令牌判定套餐。

开启校验：

```bash
# 1. 取账号服务公钥（publicKey 为 SPKI DER 的 base64）
curl -s <账号服务地址>/api/license/public-key

# 2. 写入 deploy/.env
ARBPILOT_LICENSE_REQUIRED=true
ARBPILOT_LICENSE_PUBLIC_KEY=<上一步返回的 publicKey>

# 3. 重新启动执行器
docker compose -f deploy/docker-compose.yml --env-file deploy/.env up -d
```

> 公钥配错或令牌未同步时，付费模块会被拒绝（`license_required`）。先在桌面端「设置 → 订阅与账单」确认「执行器授权」显示为有效，再打开开关。

## 第 1 步：购买服务器

推荐配置：

- **CPU / 内存**：2 vCPU / 2 GB 起（首次构建要编译 Rust，内存紧张时按第 2 步加 swap）
- **磁盘**：20 GB SSD 起
- **系统**：Ubuntu 22.04 或 24.04 LTS，x86_64
- **地区**：香港、新加坡、东京、首尔等（免备案，到交易所延迟低）；不要选中国大陆机房
- **网络**：能正常访问交易所域名与 GitHub
- **安全组 / 防火墙**：默认只放行 `22`（SSH）；如需用 IP 直连执行器，按第 4 步方式 B 放行 `8787` 并限制来源 IP。`5432` **不要**放行

## 第 2 步：准备服务器

打开终端登录一次，确认能连上、并加好 swap（2 GB 内存必须）：

```bash
ssh root@<服务器IP>
```

内存 2 GB 建议加 2 GB swap，避免首次编译被 OOM 杀掉：

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

只需要做这一步。之后**不用再登录服务器**，代码下载、Docker 安装、构建、启动都由客户端完成。

## 第 3 步：部署执行器

两种方式任选一种，结果完全一样：都会安装 Docker、构建并启动 `executor` 与 `postgres` 两个容器（自托管的数据都在你自己的服务器上）。

### 方式 A：客户端一键部署

打开桌面端 → 左侧 **文档** → 「服务器连接」卡片，填写：

| 字段 | 填写 |
|---|---|
| 服务器地址 | 服务器公网 IP 或域名 |
| 端口 | SSH 端口，默认 `22` |
| 账号 | `root`，或带 sudo 权限的普通账号 |
| 认证方式 | 密码 或 私钥（推荐私钥） |
| 密码 / 私钥 | 服务器登录密码，或粘贴私钥内容（PuTTY 生成的 `.ppk` 请先转成 OpenSSH 格式） |
| 安装目录 | 默认 `/opt/arbpilot`，保持默认即可 |

然后：

1. 点 **测试连接**：客户端会用 SSH 登录一次性探测，显示服务器当前版本与是否 root；
2. 点 **检查更新**：读取最新发布版本，和服务器上的版本比对；
3. 点 **一键部署 / 更新**：客户端自动完成下载、校验、解包、安装，日志实时显示在页面下方。

客户端在远端执行的动作与手动部署完全一样：

1. 下载发布包并按 `sha256` 校验；
2. 安装 Docker（未安装时使用官方脚本）；
3. 生成 `deploy/.env`：随机 `ARBPILOT_API_TOKEN` 与数据库密码，文件权限 `600`；
4. 构建并启动 `executor` 与 `postgres` 两个容器；
5. 轮询 `/api/v1/health`，确认执行器就绪；
6. 打印执行器地址与访问令牌，客户端从日志中解析令牌并自动填入「设置 → 执行器连接」。

重复执行不会覆盖已有数据：`deploy/.env`、数据卷都会保留，升级时直接点一次「更新」即可。

> 服务器凭据只写入本机系统钥匙串（macOS 钥匙串 / Windows 凭据管理器），不上传、不落盘到明文文件。换电脑后需要重新填写。

### 方式 B：登录服务器用命令部署

不想在客户端保存服务器凭据，或习惯用终端，可以直接登录服务器执行一条命令（不必先 `git clone`）：

```bash
curl -fsSL https://download.arbpilot.trade/executor/install.sh | sudo bash
```

脚本会依次完成：

1. 读取发布清单 `https://download.arbpilot.trade/executor/manifest.json`，取最新版本与下载地址；
2. 下载部署包并校验 `sha256`；
3. 解包到 `/opt/arbpilot`（已有的 `deploy/.env` 会保留，不会被覆盖）；
4. 安装 Docker（未安装时）并构建、启动 `executor` 与 `postgres`；
5. 生成随机访问令牌与数据库密码写入 `deploy/.env`（权限 `600`）；
6. 安装管理命令 `arbpilot`，并打印执行器地址与访问令牌。

后续升级用同一条命令，或直接用管理命令：

```bash
sudo arbpilot update     # 拉取最新版本并重启（保留令牌与数据）
sudo arbpilot status     # 容器状态 + 健康检查
sudo arbpilot token      # 打印访问令牌
sudo arbpilot logs -f    # 跟随执行器日志
sudo arbpilot restart    # 只重启执行器
```

退出登录后再登录服务器，`arbpilot` 依然可用（装在 `/usr/local/bin`）。

> PostgreSQL 由 `deploy/docker-compose.yml` 一并部署，数据卷是 `arbpilot_arbpilot-pgdata`；账户凭证与风控限额在 `arbpilot_arbpilot-data`。升级只替换代码，两个卷都不会被清空。

### 部署失败怎么办

- **认证失败**：确认端口与账号，`root` 账户只能用密码或私钥登录；禁用了密码登录的服务器请改用私钥。
- **sudo 失败**：非 root 账号需要密码，客户端会用这个密码自动 `sudo`；账号不在 sudoers 里时请改用 root。
- **下载超时**：服务器访问 `download.arbpilot.trade` 不稳定，重试一次；反复失败可在服务器上配好代理后重试。
- **构建被 kill**：内存不足，回到第 2 步加 swap 后重新点「一键部署」。


## 第 4 步：让桌面端连上执行器

一键部署成功后，客户端已经自动把「执行器地址」和「访问令牌」填好（地址为本机 `127.0.0.1:8787`）。你只差一条隧道。

### 方式 A：SSH 隧道（推荐）

在你自己的电脑上保持一条隧道，把服务器的 8787 映射到本机：

```bash
ssh -N -L 8787:127.0.0.1:8787 root@<服务器IP>
```

然后打开桌面端 → **设置 → 执行器连接**，确认地址与令牌已填好，点「保存并连接」。连接卡片右上角的徽标应显示「本地」（因为流量经隧道到了本机端口）。

令牌没自动填上时（例如日志被截断），在服务器上执行 `sudo arbpilot token` 取出（或 `grep ARBPILOT_API_TOKEN /opt/arbpilot/deploy/.env`），或在客户端 **文档** 页点一次「测试连接」后重试部署。

关掉终端隧道后桌面端会断线，重新执行那条 `ssh -N -L ...` 即可。

Windows 可以用 PowerShell 自带的 `ssh`，命令相同；也可以把这条命令存成快捷方式。

### 方式 B：公网 HTTPS（多台设备长期访问时）

不想每次开隧道，可以给执行器套一层带证书的反向代理，例如 Caddy：

1. 域名 A 记录指向服务器 IP，安全组放行 `80`、`443`；
2. 安装 Caddy 后写入 `/etc/caddy/Caddyfile`：

```caddyfile
exec.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

3. `systemctl reload caddy`；
4. 桌面端「执行器地址」填 `https://exec.example.com`，令牌不变。

如果不想配域名和证书，也可以直接用 IP 直连（桌面端地址支持 `http://45.76.177.242:8787` 这种形式）：

1. 重新部署时带上 `ARBPILOT_EXECUTOR_HOST=0.0.0.0`，让 compose 把 8787 绑到服务器网卡；
2. 只在**指定来源 IP** 上放行 `8787`（见下方"限制来源 IP"）；
3. 桌面端「执行器地址」填 `http://<服务器IP>:8787`，令牌不变。

### 限制来源 IP（IP 直连必做）

Docker 发布端口走 `FORWARD`/`DNAT`，会**绕过 ufw**：只用 `ufw allow from <你的IP> to any port 8787` 时，公网其他地址仍能连上。必须把规则写进 `DOCKER-USER` 链。

```bash
# 白名单：填你本机的固定出口 IP，多个用空格分隔
cat > /etc/default/arbpilot-fw <<'EOF'
ARBPILOT_ALLOW_IPS="203.0.113.10"
ARBPILOT_EXECUTOR_PORT=8787
EOF

cat > /usr/local/sbin/arbpilot-fw.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
[ -r /etc/default/arbpilot-fw ] && . /etc/default/arbpilot-fw
ALLOW_IPS="${ARBPILOT_ALLOW_IPS:-}"
PORT="${ARBPILOT_EXECUTOR_PORT:-8787}"
iptables -N DOCKER-USER 2>/dev/null || true
while :; do
  rule=$(iptables -S DOCKER-USER | grep -m1 -e "--dport ${PORT} " || true)
  [ -z "$rule" ] && break
  iptables ${rule/-A DOCKER-USER/-D DOCKER-USER}
done
for ip in ${ALLOW_IPS//,/ }; do
  [ -n "$ip" ] && iptables -A DOCKER-USER -p tcp --dport "$PORT" -s "$ip" -j RETURN
done
iptables -A DOCKER-USER -p tcp --dport "$PORT" -j DROP
EOF
chmod 755 /usr/local/sbin/arbpilot-fw.sh && /usr/local/sbin/arbpilot-fw.sh

# docker 每次启动都会重建 DOCKER-USER 链，重启后要重新下发
mkdir -p /etc/systemd/system/docker.service.d
printf '[Service]\nExecStartPost=-/usr/local/sbin/arbpilot-fw.sh\n' \
  > /etc/systemd/system/docker.service.d/arbpilot-fw.conf
systemctl daemon-reload
```

验证：本机 `curl http://<服务器IP>:8787/api/v1/health` 返回 `200`；用手机热点或其他网络再试应超时。

家庭宽带出口 IP 可能会在运营商地址池内漂移，此时把白名单改成网段（如 `101.71.37.0/24`），或改用隧道 / 反向代理 + 域名。

注意事项：

- 执行器**访问令牌等于完整控制权**（可下单、可读账户），必须使用脚本生成的强随机令牌；
- 建议在反向代理上再加一层 Basic Auth 或 IP 白名单；
- 直连 IP 时至少限制来源 IP，不要长期对整个公网开放 `8787`。

## 第 5 步：导入交易账户

总览 → 「导入账号」：

- **CEX**（Binance / OKX / Bybit / Bitget / Gate / Aster）：填 API Key、Secret，OKX 与 Bitget 另需 Passphrase。建议在交易所只授予读取与交易权限，关闭提现、配置 IP 白名单（填服务器出口 IP）。
- **DEX**（Hyperliquid / Lighter）：钱包地址用于查询余额，签名私钥用于本机签名下单，两者都必填。Hyperliquid 用 API Wallet（Agent）私钥，Lighter 用 API Key 私钥，不要使用主钱包私钥或助记词。

凭证写入服务器容器内的 `data/accounts.json`（权限 600，挂载在 Docker 卷 `arbpilot_arbpilot-data`），桌面端只显示前后几位。

## 第 6 步：设置风控限额

ArbPilot 没有模拟盘与实盘开关，订单通过风控后会直接提交到交易所。因此**第一次下单前**先到「设置 → 风控限额」设置单笔名义上限、总敞口上限、最大杠杆与允许的交易所/交易对，保存后立即生效。

## 日常运维

装了管理命令后，服务器上的常用操作：

```bash
sudo arbpilot status      # 容器状态、已安装版本、健康检查
sudo arbpilot logs -f     # 跟随执行器日志
sudo arbpilot update      # 升级到最新发布版本（保留令牌与数据）
sudo arbpilot restart     # 只重启执行器
```

需要直接用 compose 时（在 `/opt/arbpilot` 下）：

```bash
cd /opt/arbpilot
docker compose -f deploy/docker-compose.yml --env-file deploy/.env ps
docker compose -f deploy/docker-compose.yml --env-file deploy/.env logs -f executor
docker compose -f deploy/docker-compose.yml --env-file deploy/.env restart
```

### 备份凭证

```bash
cd /opt/arbpilot
docker run --rm \
  -v arbpilot_arbpilot-data:/data \
  -v "$PWD:/backup" \
  alpine tar czf "/backup/arbpilot-data-$(date +%F).tgz" -C /data .
```

恢复时把压缩包解开到同一个卷：

```bash
docker run --rm \
  -v arbpilot_arbpilot-data:/data \
  -v "$PWD:/backup" \
  alpine sh -c 'rm -rf /data/* && tar xzf /backup/arbpilot-data-2026-11-05.tgz -C /data'
```

数据库数据在卷 `arbpilot_arbpilot-pgdata`，同样可以这样备份。

### 配置项

需要调整的开关写在 `deploy/.env`（compose 会读取）：`ARBPILOT_FUNDING_ENABLED`、`ARBPILOT_FUNDING_SYMBOLS`、`ARBPILOT_BINANCE_FAPI_URL`、`ARBPILOT_LICENSE_REQUIRED`、`ARBPILOT_LICENSE_PUBLIC_KEY` 等；完整清单见根目录 `.env.example`。修改后执行一次 `up -d` 生效。

策略始终在订阅者自己的执行器上运行：发布只是把该版本的 WASM 交付物和参数定义挂到市场，订阅者授权后导入到自己的执行器再启动；作者与订阅者的运行实例都记录在 `strategy_runs`、`strategy_run_events`，随数据库一起持久化，客户端策略详情页可直接查看。

## 常见问题

**桌面端提示无法连接 / 401**

- 401：令牌不一致。服务器上执行 `grep ARBPILOT_API_TOKEN deploy/.env`，与设置页比对。
- 连接被拒绝：隧道没开；或想用 IP 直连但执行器仍只绑定回环地址（需要 `ARBPILOT_EXECUTOR_HOST=0.0.0.0` 并放行端口）。

**容器起不来、编译被 kill**

内存不足。按第 2 步加 swap，然后在客户端 **文档** 页重新点一次「一键部署」。

**文档页按钮是灰的 / 提示「请在桌面端运行」**

部署功能依赖桌面端的 SSH 能力，浏览器里打开预览地址时不可用。请用安装好的 ArbPilot 客户端。

**客户端没有服务器密码，或者想换一台电脑部署**

服务器凭据只存本机系统钥匙串，不会同步。在新电脑上重新填一次即可，服务器上的数据不受影响。

**怎么知道有没有新版本**

打开 **文档** 页会自动检查一次；也可以随时点「检查更新」。显示「已是最新」时不需要操作，有更新时按钮会变成「更新到 x.y.z」。

**服务器访问交易所超时**

给执行器配置代理：在 `deploy/.env` 加 `ARBPILOT_MARKET_PROXY=http://<代理地址>:<端口>`，再 `up -d`。

**重启后导入的账户不见了**

确认 compose 里 executor 挂了 `arbpilot-data:/home/arbpilot/data` 卷（本仓库默认已配置）。旧版本没有该卷时，账户文件会随容器删除而丢失，需要重新导入。

**想换回内置执行器**

设置 → 执行器连接：选「内置执行器」后保存，交易与数据都回到本机；选「官方托管」时只保留行情与资讯，账户与下单不可用。

## 非自托管用户

不需要购买服务器，也不需要执行本文任何命令：

- 安装包内置执行器（sidecar），启动时自动拉起并把数据写入本机 SQLite，无需安装 PostgreSQL；
- 交易所 API Key 与订单只留在本机，官方服务器不接触；
- 行情、资金费率与新闻来自官方只读数据接口（构建时由 `VITE_ARBPILOT_DATA_URL` 注入，留空则直接用本机采集）；
- 只有想改连自己的服务器时，才需要第 4 步的配置。

## 客户端自身的更新

客户端和执行器是两套版本，各自独立更新：

- **执行器**：文档页「一键部署 / 更新」；
- **客户端**：设置页「客户端更新」。

操作：设置 → 「客户端更新」→ **检查更新** → 有新版本时点 **下载并安装** → **立即重启**。

- 版本清单来自 `https://download.arbpilot.trade/desktop/latest.json`，安装包带签名校验，签名不符会拒绝安装；
- 下载走增量替换，重启后即切到新版本；
- 只替换客户端本体：执行器、服务器数据、本机登录状态与执行器连接配置都保留。

## 附：发布新版本（维护者）

两个发布源互不影响：

| 内容 | 清单地址 | 打包脚本 |
|---|---|---|
| 执行器（服务器） | `https://download.arbpilot.trade/executor/manifest.json` | `deploy/package.sh` |
| 桌面客户端 | `https://download.arbpilot.trade/desktop/latest.json` | `deploy/package-desktop.sh` |

### 发布执行器版本

1. 改根目录 `Cargo.toml` 的 `version`；
2. 打包：

```bash
bash deploy/package.sh
# 自定义输出目录：bash deploy/package.sh /tmp/release
# 自定义发布域名：ARBPILOT_RELEASE_BASE_URL=https://cdn.example.com/executor bash deploy/package.sh
```

产出两个文件：

| 文件 | 说明 |
|---|---|
| `dist/release/arbpilot-executor-<version>.tar.gz` | 源码包（含 `deploy/install.sh`、compose、Dockerfile、执行器源码） |
| `dist/release/manifest.json` | `version`、`bundle_url`、`sha256`、`size`、`released_at`、`notes` |

3. 把这两个文件上传到 `https://download.arbpilot.trade/executor/`（`manifest.json` 覆盖旧的，客户端以 `cache: no-store` 拉取）；
4. 客户端打开 **文档** 页或点「检查更新」即可看到新版本，服务器版本低于 `version` 时按钮变为「更新到 x.y.z」。

客户端部署时会先校验 `sha256`，再解包执行 `deploy/install.sh`，所以包内容损坏或被替换会直接失败，不会污染服务器。

### 发布客户端版本

首次发布需要一对签名密钥（只需生成一次）：

```bash
cd apps/desktop
pnpm tauri signer generate -w ~/.tauri/arbpilot.key
```

公钥已写进 `apps/desktop/src-tauri/tauri.conf.json` 的 `plugins.updater.pubkey`；私钥默认放在 `~/.tauri/arbpilot.key`，**不要提交到仓库，务必备份**，丢失后已安装的客户端将无法验证新包。

发布步骤：

1. 改 `apps/desktop/src-tauri/tauri.conf.json` 的 `version`（客户端版本号，与执行器版本互相独立）；
2. 打包并签名。macOS 在本机执行：

```bash
bash deploy/package-desktop.sh
# 更新说明会显示在客户端更新卡片里：
ARBPILOT_DESKTOP_NOTES="修复下单确认" bash deploy/package-desktop.sh
```

Windows 交给 GitHub Actions 的 `desktop-windows` 工作流（Tauri 不支持从 macOS 交叉编译 Windows 安装包，需要 Windows runner 上的 MSVC 与 NSIS）：在仓库 Actions 页手动触发，或在推送 `desktop-v*` 标签时自动运行。首次使用前要在仓库 Secrets 里配置签名私钥：

| Secret | 值 |
|---|---|
| `TAURI_SIGNING_PRIVATE_KEY` | `~/.tauri/arbpilot.key` 的完整内容 |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | 私钥密码，没有密码则留空 |

工作流产出的 `arbpilot-desktop-windows` 压缩包里包含 `*-setup.exe`、`*.exe.sig` 与 `latest.json`。`latest.json` 会自动拉取线上同一版本的清单并合并 `darwin-*` 条目，所以直接用它覆盖线上文件即可。

macOS 与 Windows 都产出 `dist/desktop/latest.json` 与对应平台的安装包（`.app.tar.gz` / `*-setup.exe`）及其 `.sig` 签名。

3. 把安装包、`.sig` 与 `latest.json` 上传到 `https://download.arbpilot.trade/desktop/`；
4. 客户端「设置 → 客户端更新 → 检查更新」即可发现新版本。

只想本地打一个不签名的安装包时，跳过更新制品：

```bash
cd apps/desktop
pnpm tauri build --config '{"bundle":{"createUpdaterArtifacts":false}}'
```
